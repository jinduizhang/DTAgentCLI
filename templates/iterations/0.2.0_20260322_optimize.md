# 迭代快照: v0.2.0 - 2026-03-22

## 变更摘要

优化命令体系，新增 diff-ut 和 fix-ut 目录级修复，简化 DT_AGENTS.md 生成，完善端到端流程。

## 详细变更

### 新增

1. **`/diff-ut` 命令**
   - 本地变更 UT 分析（提交前检查）
   - 支持 `--base` 参数指定基准分支
   - 不传参数时分析工作区变更（未 commit）
   - 与 `/mr-ut` 区分：mr-ut 用于已提交 MR，diff-ut 用于本地变更

2. **`/task-status-dt` 命令**
   - 查看批量任务执行进度
   - 显示成功/失败/待执行数量

3. **`/fix-ut` 目录级修复**
   - 参数识别：类名/文件路径 → 单个修复，目录 → 批量修复
   - 批量修复流程：
     1. 从 DT_AGENTS.md 读取 Maven 配置
     2. 整体编译验证（mvn test-compile）
     3. 修复编译错误
     4. 创建任务队列逐个修复

4. **dtagent 代理禁止事项**
   - 严禁修复业务代码
   - 只能修改 `src/test/java/` 下的测试代码

### 修改

1. **命令重命名**
   - `/generate-single` → `/generate-dt-single`
   - `/generate-dir` → `/generate-dt-dir`
   - 统一 `-dt` 后缀

2. **`/generate-dt-dir` 参数校验**
   - `{dir}` 为必需参数，无默认值
   - 未输入目录时输出提示并终止

3. **`/init-dt` 简化**
   - 从 `.idea/workspace.xml` 提取 Maven 配置（settings/profiles/JVM参数）
   - DT_AGENTS.md 只包含必要信息：
     - 测试框架版本
     - Maven 命令（带自定义参数，可直接使用）
     - Given-When-Then 模式规范
     - 命名规范
   - 删除冗余的测试类模板和经验提取

4. **Session 查看方式**
   - 修正为 `/sessions` 命令
   - 删除错误的"右侧任务栏"描述

5. **dtagent 代理配置**
   - 禁用 task 工具，避免子任务挂起
   - 设置 `default_agent: dtagent`

### 删除

1. 删除 `docs/init-guide.md` 和 `docs/packaging.md`（内容已合并到新文档）
2. 删除 `templates/skills/*/experiences/spring-boot-test.md` 和 `diamond-mock.md`

## 待讨论问题（2026-03-22）

### 问题一：二方件 Mock 不准确

**现象**：生成的二方件 Mock 不准确，导致修复失败

**当前经验提取 Gap**：

| 当前提取 | 缺失 |
|---------|------|
| `@Mock` 声明 | 二方件初始化方式 |
| `when().thenReturn()` | 二方件 API 签名 |
| 简单 Mock 模式 | 二方件依赖关系 |
| - | 二方件常见错误 |
| - | 二方件配置来源 |

**问题根因**：
```
@Mock
private DiamondClient diamondClient;

// 提取到这里就停了，缺失：
// 1. diamondClient 如何初始化？
// 2. diamondClient.get() 返回什么类型？
// 3. diamondClient 有哪些方法？
// 4. 二方件的配置从哪来？
```

### 问题二：批量生成编译错误影响其他任务

**现象**：批量生成时，一个任务的编译错误会影响其他任务

**根因**：
1. generate-java-ut 没有编译验证环节
2. Mock 类型推断不准确
3. 缺少 import 自动补全

## 已确定方案

### fix-java-ut 优化

```
阶段1: 编译验证（必须成功，无次数限制）
  循环修复直到编译通过
  
阶段2: 运行验证（最多10次）
  循环修复，每次修复后重新编译
  ├─ 成功 → 进入覆盖率提升
  └─ 10次失败 → 最终编译验证 → 确保编译OK → 终止
  
核心保证：最终代码必须可编译（即使运行失败）
```
