# 优化过程记录

## 背景

### 原始问题

用户反馈任务队列执行缓慢，尝试并行执行时遇到 Maven 编译冲突。

```
场景:
- 生成 10 个测试类的测试代码
- 使用 batchSize=4 并行执行
- 结果: Maven 编译失败，target 目录冲突
```

### 需求分析

**用户需求**:
1. 提高任务队列执行效率
2. 支持并行执行无冲突
3. 基于类级（文件级）并行
4. 利用现有 batchSize 参数

**约束条件**:
1. 不修改用户源码目录
2. 任务完成后清理临时文件
3. 支持 Windows 和 Unix
4. 先验证方案再实现

---

## 方案设计

### 第一阶段：方案讨论

**讨论要点**:

1. **隔离级别选择**
   - 方案 A: 完全类级隔离（每个类独立工作目录）✅
   - 方案 B: 目录级隔离（同目录串行，不同目录并行）❌
   
   **决策**: 选择方案 A，更简单，并行度更高

2. **软链接策略**
   - Windows: junction（目录）+ 硬链接（文件）
   - Unix: 符号链接
   
   **决策**: Windows 使用 junction，无需管理员权限

3. **生命周期管理**
   - 创建: 任务开始时
   - 清理: 任务完成后立即清理 ✅
   - 保留: 失败时保留供调试 ❌
   
   **决策**: 立即清理，不保留

### 第二阶段：原型验证

**验证内容**:

| 验证项 | 方法 | 结果 |
|--------|------|------|
| 软链接创建 | 创建 junction 链接 | ✅ 通过 |
| 独立 .m2 编译 | `mvn -Dmaven.repo.local` | ✅ 通过 |
| 并行编译隔离 | 同时运行 2 个 Maven 编译 | ✅ 通过 |
| 性能对比 | 串行 vs 并行 | ✅ 1.19x 加速 |

**验证代码**: `.sisyphus/scripts/workspace-isolation-prototype.ts`

**验证结论**: 方案可行，可以继续核心实现

### 第三阶段：核心实现

#### 任务 4: WorkspaceManager 模块

**实现内容**:
```typescript
// src/core/workspace-manager.ts
class WorkspaceManager {
  createWorkspace(taskId: string)  // 创建工作目录
  cleanupWorkspace(taskId: string) // 清理工作目录
  cleanupAll()                     // 清理所有
}
```

**关键点**:
- Windows junction 软链接
- 独立 .m2 目录
- 异常处理

**耗时**: 30 分钟

#### 任务 5: TaskManager 集成

**实现内容**:
1. 导入 WorkspaceManager
2. 扩展 QueueState 接口
3. 修改 executeTask 函数
4. 修改 task-start 工具

**关键点**:
- 只在 batchSize > 1 时创建工作空间
- 在 prompt 中注入工作空间信息
- 任务完成后自动清理

**耗时**: 45 分钟

#### 任务 6: 清理机制

**实现内容**:
1. executeTask 中 try-finally 清理
2. task-stop 中 cleanupAll

**关键点**:
- 成功/失败都清理
- Windows 先删除软链接再删目录

**耗时**: 15 分钟

## 遇到的问题

### 问题 1: Windows 软链接权限

**现象**: 符号链接需要管理员权限

**解决**: 使用 junction 软链接（目录）和硬链接（文件）

### 问题 2: Windows 删除软链接

**现象**: `fs.rmSync` 删除 junction 时报错

**解决**: 先删除软链接，再删除目录

### 问题 3: Agent 如何使用工作空间

**现象**: Agent 不知道工作空间路径

**解决**: 在 prompt 中注入工作空间信息和 Maven 参数

## 经验总结

### 成功经验

1. **先验证再实现**: 原型验证避免了方案不可行的风险
2. **用户参与决策**: 关键决策点让用户确认，避免返工
3. **简单优先**: 选择最简单的实现方式（类级隔离）

### 改进建议

1. **依赖缓存**: 多个 .m2 仓库可共享依赖，减少磁盘占用
2. **预编译**: 批量任务前预编译，加速后续任务
3. **监控**: 添加工作空间大小监控
